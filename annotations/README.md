# 图文标记数据

`annotations/*.json` 是网站图文导览的最终数据源。通用生成脚本只负责为缺少标记文件的币种生成初稿，默认不会覆盖已经由编辑器校准过的 JSON。

## 本地编辑

在项目根目录运行：

```bash
python3 annotations/editor_server.py
```

然后访问：

```text
http://127.0.0.1:8001/annotation_editor.html
```

编辑器支持：

- 拖动矩形、椭圆或多边形区域；
- 拖动控制点调整大小或多边形顶点；
- 方向键微调位置，`Shift` 加大步长，`Alt + 方向键` 调整宽高；
- 增删文字标记和区域；
- 描述中出现重复文字时，根据选区自动记录并维护第几处匹配；
- 直接修正当前币面的描述；
- 撤销、重做、浏览器草稿、下载或复制 JSON；
- 通过 8001 端口的本地编辑服务，将标记 JSON 和币面描述分别保存到 `annotations/<id>.json` 与 `coin_data.json`；
- 将全部币种的审核进度保存到 `annotations/review_progress.json`，可通过 Git 在不同电脑或浏览器之间接力。
- 在审核进度区点击“定位未审核面”，可按顺序直接跳到尚未审核的币种和币面。

服务只监听 `127.0.0.1`。保存前会同时校验币面描述、标记原文、图片路径和区域坐标，再以临时文件替换方式写入；其中任一文件替换失败时会回滚 `coin_data.json`。

## 文件与币面的对应关系

- `coin_data.json` 保存钱币资料和两面的完整文字描述；
- `annotations/<id>.json` 保存描述原文与图片区域之间的映射；
- `f` 表示第一张图片，对应 `coins/img/<id>_f.webp` 和 `coin_data.json` 的 `description`；
- `b` 表示第二张图片，对应 `coins/img/<id>_b.webp` 和 `coin_data.json` 的 `description2`。

纪念币与纪念钞在网站大图中的“正面/反面”显示顺序由网站处理，不需要为此交换上述数据文件中的 `f`、`b`。

## 修正已有币种

如果发现已有币种的标记位置、标记文字或币面描述有误：

1. 启动本地编辑服务并在编辑器中选择对应编号；也可以用 `annotation_editor.html?id=<编号>` 直接打开；
2. 如果浏览器中存在过期草稿，点击“从文件重载”，以项目文件为准重新开始；
3. 修正标记时，可以移动或缩放区域、修改区域形状、增删区域、增删标记，以及调整标记顺序；
4. 如果 `coin_data.json` 中的币面描述有错漏，可以直接修改图片下方的描述文本框；
5. 描述修改后，同步检查各标记的“描述中的原文”，确保原文仍能在当前币面描述中完整找到；
6. 分别检查第一图和第二图，确认无误后点击“保存到项目”。

一次保存会同时更新两个位置：

- 标记内容和区域写入 `annotations/<id>.json`；
- 第一图、第二图的描述分别写入 `coin_data.json` 的 `description`、`description2`。

因此，修正已有币种时不需要再手工打开另一个 JSON 修改描述。保存服务会先校验两个文件，避免出现描述已经改变、标记原文却无法匹配的情况。

当相同的标记原文在币面描述中出现多次时，编辑器会根据新增标记时的文字选区自动写入 `occurrence`，例如第二处写为 `"occurrence": 2`。唯一匹配和第一处匹配不写该字段；描述修改后如果只剩唯一匹配，保存时会自动删除已经多余的 `occurrence`。删除标记本身不会改变其他标记指向的文字位置。

## 添加新币种并人工审核

1. 在 `coin_data.json` 中新增币种资料，至少准备好编号、名称、年份、两张图片信息，以及 `description`、`description2` 两面的完整描述；
2. 准备本地图片 `coins/img/<id>_f.webp` 和 `coins/img/<id>_b.webp`；
3. 启动本地编辑服务，打开 `annotation_editor.html?id=<编号>`；编辑器发现缺少 `annotations/<id>.json` 时，会自动根据两面的描述生成标记初稿，不需要手动运行脚本；
4. 确认页面显示“新币标记初稿未保存”；此时初稿只存在于编辑器中，尚未写入项目；
5. 对第一图和第二图逐项人工审核；
6. 审核完成后点击“保存到项目”，并在编辑器中标记该币面已审核。

人工审核时至少确认：

- 图片、币面描述和 `f`、`b` 的对应关系正确；
- 描述中的重要人物、物品、文字和场景都有对应标记；
- 自动生成但含义不准确的标记已经删除，遗漏的标记已经新增；
- 每个标记的原文与描述完全一致，名称清楚易懂；
- 区域位置、大小和形状能准确指向图中主体，没有明显覆盖无关内容；
- 两个币面都已经检查并保存。

编辑器中的审核进度保存在 `annotations/review_progress.json`。首次使用新版编辑器时，浏览器中原有的审核进度会自动合并到该文件。通过 Git 接力时，需要一并提交 `coin_data.json`、`annotations/<id>.json` 和 `annotations/review_progress.json`。

## 可选的批量生成脚本

通常不需要手动运行脚本。只有一次加入多枚新币、希望批量提前创建标记文件时，才运行：

```bash
node annotations/generate_annotations.js
```

脚本与编辑器共用同一套初稿生成逻辑，只创建缺失文件，不会覆盖任何已有标记。已有标记统一通过编辑器修订。

日常新增单枚币种时，直接打开编辑器完成自动生成、人工校准和保存即可。
